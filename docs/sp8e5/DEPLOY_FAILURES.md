# Deployment/retirement contract (written before implementation)

This tool is written for root to review and execute serially. Authoring/import/help must not connect to a device or alter it. Default is dry-run; validation may use a temporary bare repository with read-only alternates, but production refs/index/worktree/profile/pin stay unchanged until `--apply`.

Pinned identities: hostname comma-9c13c9f5; repository /data/openpilot; old branch sp-dev-mac at 7bd33b5ca7d93f91bcb73c2947a045e06847f244; candidate dev-sp-8E5 descended from dev-sp-egpu b6ceca145001958f88c686d57feac8c9e8a7073c. Never replace Panda/opendbc/msgq/tinygrad gitlinks, initialize/update submodules, force-reset, clean, drop a stash, fetch unrelated refs, or delete another branch.

Failures to detect before/during changes: wrong machine/checkout/old HEAD; active model/camera or unsafe/stale physical guard; remote control requested; malformed/wrong bundle/ref/commit/base; changed gitlinks/submodule HEAD/dirty submodule; failed or stale/incompatible full/compact proof; backup collisions/space shortage/unstable files; incomplete archive/readback; losing staged or ignored/untracked work; racing checkout edits; unknown observer changes beyond the reviewed 2-added/1-deleted lines; reusing wifi helper against changed source; changing persistent profile fields beyond result_schema; pin readback mismatch; candidate file bytes/modes different from commit; missing rollback ref/bundle/stash; another branch/ref changing; interrupted install; failed rollback conflicts; retirement before post-install real-camera completion, without hardware restoration, with actual CAN, or using unmatched source evidence.

Install backs up refs, old branch/HEAD, submodule states, porcelain status, both staged/unstaged binary diffs, every tracked dirty and untracked/ignored file (including prebuilt), exact profile/pin bytes and metadata, and a small old-branch bundle relative to the existing base. It creates a unique backup ref, fetches only the candidate branch, records the exact stash object from `stash -u`, switches without overwriting ignored files, and restores only explicitly reviewed incidental files. Stashes and backup refs are retained. A failed install attempts a guarded rollback; if physical state is unsafe, recovery is explicitly deferred rather than forcing an onroad checkout.

Retirement requires the exact installed branch/commit, an intact backup ref/bundle, and post-install acceptance: real cameras and production processes, completed requested duration, no failure, hardware_restored.complete, road qualification false, zero actual vehicle/CAN publication, file-only actuator records, source-sha256.json matching installation readback. The old ref must still equal its exact pinned HEAD and cannot be checked out in another worktree. Delete only that ref using an expected-old-value update.

Rollback preserves any candidate-side work in another recorded stash, restores the old ref from its verified bundle if retired, switches back without discarding changes, applies the recorded original stash with its index, restores exact profile/pin snapshots and confirms the original status. It never drops either stash or removes the candidate branch. Every mutation is recorded in a durable state directory; rollback archives are recovery evidence, not inputs to a blind tar extraction.

## First device deployment findings (before fixes)

1. A real Git LFS checkout can contain hydrated bytes whose raw Git blob differs from the committed pointer. The 349-byte favicon was incorrectly rejected against its 128-byte pointer. Accept only a valid committed LFS pointer with `filter=lfs`, exact materialized SHA256 and exact declared size; reject corrupted materialized bytes and unrelated filters. Do not substitute `git hash-object` as an unchecked blanket bypass.
2. An original untracked Wi-Fi helper became ignored in the candidate. `stash -u` preserved candidate work but left that ignored file; old-stash apply restored all source/index changes and returned nonzero for the already-present identical helper. Keep all archive/stash copies. A nonzero apply may only be accepted after exact original status, every backed-up dirty/untracked file SHA/mode and the complete original staged index match. Restoration of profile/pin must still run once the old checkout is active, even if a Git recovery step reports an error; never mark a partial recovery complete.
3. The next candidate is a child of the already-fetched candidate ref. Permit only verified fast-forward ancestry in the validated bundle scratch repository; bind the observed existing ref through to fetch and continue using an ordinary non-forced fetch. Reject unrelated or moved refs.

`deploy_lifecycle_e2e.py` will create real temporary Git repositories, enable the real Git LFS clean/smudge filter, exercise binary backup/stash/switch/rollback, reproduce the ignored-to-untracked collision, and exercise valid/invalid fast-forward candidate bundles. Device identity/physical guard and phone qualification are explicit fixture boundaries; it never operates on /data/openpilot or a device. Run the unchanged production tool first to retain failing baselines, then run the same lifecycle after fixes. Preserve JSON command/event receipts, state files and fixture bundles.
