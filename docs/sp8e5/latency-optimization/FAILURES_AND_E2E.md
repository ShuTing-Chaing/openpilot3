# OPIF 延迟优化：先列失败，再验证

目标设备：C3XL `comma-9c13c9f5`，一加 15T `3B168600EWF00000`。目标源码：`dev-sp-8E5`。本页是实施前的验收合同；实际设备身份、offroad、未接管和源码哈希每次重跑均需重新读回。

## 可能失败的方式

1. 旧版与新版测试顺序造成热浸、时钟或供电漂移，被误认为模型图回归。
2. ADB/logcat/profiler 本身改变 `Run()` 分布；采样太频繁也会扰动手机。
3. 电池温度正常，但 CPU/HTP 结温或频率已变化；读取不到 HTP 计数器时不能把 CPU 频率当替代证明。
4. `Session.Run()`、手机处理、C3 提交到收到、相机 EOF 到发布是不同口径，不能相减后当作已定位的网络开销。
5. 结果晚到、乱序、断线、历史重置或输出字节变化，表面 p50 改善却破坏 20 Hz 与本地热备。
6. 本地测试与道路运行条件不同，短测成功后 p99 或长时间热稳态变差。
7. 热点没有互联网时 Android 已保存网络不自动关联；主动请求 Wi-Fi 仍可能需要一次用户授权，ROM 也可能拒绝请求。
8. 新热点网络接管默认路由、影响 App 其他流量，或中断 USB 优先的推理；断线后 socket 走错接口。
9. 手动启动 App 后 Wi-Fi 请求未发出，或重复启动泄露回调。
10. 手机随机 MAC 变化后，C3 固定 MAC 绑定失效；旧 ARP 邻居仍残留，不能把它误认成当前手机。
11. 专用热点上同时有多个可达客户端、ICMP 被手机阻断，或邻居数量超界时，MAC 无关的发现必须拒绝猜测端点，本地小模型继续输出。

## E2E 步骤和门禁

1. **基线身份与安全门**：读回 C3/手机身份、分支、源码及 APK 哈希；C3 必须 `IsOffroad=1`、`IsEngaged=0`，控制 profile 仍禁用真实控制。保存电池、供电、热状态和测试前网络状态。
2. **无探针基线**：用现有 `tools/sp8e5/phone_e2e.py`，固定同一 `current-input.npz`、20 Hz、200 帧、USB、同一 App 和精简结果协议。保留每帧原始 `Run()`、C3 收到年龄、输出哈希与 `REPORT.json`。
3. **探针对照**：在同一 App 上做无探针→有探针→无探针，逐帧对齐手机 CPU 频率、可读 thermal zone、电池电流/电压。采样间隔 100–200 ms；探针若显著改变分布，停止用其定位性能。
4. **定位后只改一个机制**：先证明是时钟/供电、HTP 图执行、历史 I/O、JNI 外侧或 C3 往返的哪一段；没有可复现的 ms 级开销就跳过对应重写。保留原 ABI、历史顺序、D2、200 ms 丢帧和本地模型每帧热备。
5. **同底座 A/B/A**：至少 200 帧每轮，输入和 profile 哈希相同，输出逐字节相同且 0 缺失/乱序；比较 `Run()` p50/p95/p99、C3 收到年龄、最长无有效输出间隔。若 p99、输出或回退恶化，回滚候选。
6. **热点单独验收**：手动启动 App 后，证明手机经无互联网热点能连通 C3，并且默认互联网路由保持原路径；USB 断开时 20 Hz 固定输入重跑，输出逐字节相同。断热点时本地模型持续输出，恢复后建立新历史会话。冷启动自动拉起不在用户要求的范围内。
7. **可复跑产物**：每轮保存命令、身份/哈希、环境采样 JSONL、逐帧结果、统计、失败原因和恢复读回。离车通过只表示台架通过，不表示 onroad 资格。
8. **MAC 无关端点发现**：更换手机随机 MAC 后，用真实 C3 热点和唯一可达客户端验证端点；注入旧邻居、两个可达客户端、ICMP 不通和 USB 中断，逐项证明拒绝错误端点、本地热备不断流。新发现代码须完成这些 E2E 后才能进入原有源码哈希资格清单。
