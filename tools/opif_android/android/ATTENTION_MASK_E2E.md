# OPIF attention mask 优化：失败方式与离线 E2E

2026-09-28，先记录本合约再实现转换。目标是把截图中的8层常量因果遮罩改写纳入OPIF自身导出；不使用NI的App或把NI的性能结果算作OPIF成绩。

## 实施前失败方式

- bool mask极性错误；8层mask不同却共用一个bias；score形状或FP16 dtype不符；错误删除被其他节点使用的Not。
- 改变原有权重、公开ABI、3个跨帧历史状态，或误把用于性能消融的Identity图当部署模型。
- 导出baseline无法重现手机OPIF安装标记对应的86890bf9…图，导致对照基线不清。
- Where→Add对任意IEEE754数据并非无条件逐位等价：被遮蔽的NaN/+Inf及负零有边界差异；有限正常输入上的代数推导不能替代完整连续图的同机比较。
- QNN对负无穷FP16常量处理不同、图编译失败或出现CPU算子回退。
- 单次计时包含编译/预热，或两个App/两个模型并发竞争，制造虚假性能收益。
- 外置图与权重缺失、APK仍装入旧模型，或缓存键未随模型内容更新。

## E2E与产物

1. 使用源文件SHA `404a18cfd86d29637d20c697dfde245bb47c666ae016730ab674c65f4d1e1aa4`，用原OPIF导出流程生成baseline，记录导出SHA及算子清单。
2. 用新增mask选项生成单文件候选。确认8个Where及其单一消费Not变为8个Add，共用一个FP16 `[1,1,288,288]`常量。检查原始initializer逐字节、公开ABI和其它节点保持不变。
3. 同一手机、OPIF运行库、同样持续高性能和图优化配置，独立离线工具比较410帧四个输出，双方独立推进历史。只比较OPIF准备图与其mask候选，不使用Mac/小模型作为数值参考。
4. 单模型驻留分别做A/B/A，预热后保存逐帧推理耗时与环境信息。延迟汇总报告p50/p95/p99/max；不能把截图17.9ms作为本机已完成结果。NPU推理耗时和C3端到端帧龄分开统计。
5. 导出和离线对照不加入onroad执行路径，不新增认证、配对、在线对比或等待。已安装App不由导出工具修改。若设备当时在行驶或无法独占测试，保留候选与完整复跑步骤，明确手机测量未完成。

## 截图其它方向的采用范围

- 残差Add、LayerNorm、Softmax、Gelu等正常数学计算保留。Identity替换只是一种耗时消融，不是优化后的功能图。
- QNN持续高性能已在OPIF实现；DCVS_V3_EXP/CENG_EXP等额外投票不依据截图盲开。
- FC布局、共享内存、状态/输出预分配、DDR吞吐需用本机profile确认，再作为独立候选衡量。截图中的76GB/s、35GB/s和DDR档位收益不作为本机测量。
